# Reproducing the trajectory model

Everything needed to rebuild the deployed GRU from public data is in this repository. The training data (about 28 GB locally) is **not** committed
because it is regenerated by the scripts below from adsb.lol's public releases.

All commands run from the repository root. The scripts live in `ml/scratch/` (one-off experiment scripts, excluded from lint).

| Step | Command | Output |
|---|---|---|
| 0. Survey the days first (reads only 256 KB pieces) | `python3 ml/scratch/survey_days.py --rounds 1` | verdict per day: OK, WARN or MISSING |
| 1. Extract Europe tracks per day | `python3 ml/scratch/extract_globe_day.py --round 1` (or `--dates 2026.09.15`; add `--mb 60 --out data/globe_extract_smoke` for a quick test) | `data/globe_extract/<day>_pNN.parquet` on a 10 s grid |
| 2. Check the data | `python3 ml/scratch/check_data_quality.py`, `python3 ml/scratch/validate_extras.py` | physics and coverage checks on the extra fields |
| 3. Build training windows | `python3 ml/scratch/build_windows_v2.py` (`--smoke` for 2 days) | `data/gru_v2/<split>/<day>/X.npy, S.npy, Y.npy, meta.parquet` |
| 4. Train | `python3 ml/scratch/train_gru_v2.py --data data/gru_v2 --variant B --epochs 15 --out runs/B` (Colab GPU: `ml/colab/train_gru_v2.ipynb`) | PyTorch weights, per-regime and per-horizon metrics against the straight-line baseline |
| 5. Export | `pip install onnx onnxruntime`, then `python3 ml/scratch/export_onnx.py --run runs/B --data data/gru_v2 --out runs/B/model.onnx` | `model.onnx` plus a check that ONNX and PyTorch agree |
| 6. Publish | upload `model.onnx` as `models/trajectory.onnx` and the normalisation JSON as `models/trajectory_norm.json` in the lake bucket | the predict Lambda loads them on its next cold start |

Notes
- `ml/features.py` is shared by step 3 and by the predict Lambda. If you change it, bump `FEATURES_VERSION` and retrain; the serving code refuses a mismatch.
- The deployed model is variant B with destination features (`use_extra` and `use_dest` are true in `trajectory_norm.json`).
- Ablation (variant A, core features only): `--variant A`. Results of both are in the [ML journal](liveflights-ml-journal.md).
- Retraining is a manual Colab run; it is not scheduled.
- A pre-built copy of the deployed model is attached to the GitHub release `model-2026-09-28`, see [model-card.md](model-card.md).
